
## 1. 核心理念：Everything Notebook 

很多人習慣按主題建筆記本（比如“學英語”、“學編程”），但谷歌官方博客（Steve Johnson）提出了一個更高級的理念：**創建一個主筆記本 (Everything Notebook)**。

*   **這是什麼：** 把你所有的核心資料都塞進這一個筆記本里。
*   **放什麼資料：**
    *   日常使用的常識資料、常用參考資料、書摘、知識筆記
    *   項目資料、工作/創業核心數據
    *   頭腦風暴記錄、靈感與創意想法
    *   過往的成功案例與失敗覆盤
    *   個人業務數據（如：郵件、自媒體後臺數據、粉絲畫像、評論等）
*   **目的：**
    當資料足夠全，AI 就瞭解了你的思維方式、優缺點和性格。它不再只是個工具，而是你的**數字分身**。以後做決策時，它是基於“瞭解你”的前提下，爲你量身定製方案，而不是給通用的廢話建議。

> [!TIP] 建議
> 先建好這個“主筆記本”，把它作爲你的決策大腦，然後再去建其他細分的知識筆記本。

## 3. 系統提示詞 (System Prompt)

在筆記本設置裏，可以自定義系統提示詞（最近擴容到1萬字符）。這是讓AI變聰明的核心。

### 提示詞撰寫邏輯
一個好用的通用提示詞應該考慮以下幾個部分：
1.  **定義角色**：你是分析師、產品經理還是主持人？
2.  **任務目標**：整理論點？寫決策書？
3.  **資料規則**：只用資料庫，還是可以結合訓練數據？
4.  **思考路徑**：對比觀點？先給結論再找依據？
5.  **輸出格式**：Markdown？表格？中英文對照？
6.  **語氣風格**：專業嚴謹？杜絕廢話？
7.  **負向約束**：禁止做什麼（如禁止討好、禁止模糊指代）。

**系統提示詞範例模版：**

```markdown
## 1. 角色設定
你現在的身份是：[在此處填寫角色]

示例 1 (內容創作)：一位擁有15年經驗的資深科技博主，擅長把複雜的技術概念用大白話講清楚，風格幽默且接地氣。
示例 2 (商業分析)：一位理性犀利的投資分析師，只相信數據和財報，對管理層的畫餅行爲保持高度警惕。
示例 3 (學術輔助)：一位嚴謹的科研助教，專注於梳理邏輯漏洞，要求所有觀點必須有明確的出處。

## 2. 核心任務
你的主要任務是：[在此處填寫任務]

示例 1：根據上傳的資料，整理出一份邏輯通順的視頻口播文案。
示例 2：分析上傳的會議紀要，提取出待辦事項、負責人以及潛在風險。
示例 3：作爲我的“第二大腦”，根據資料庫中的過往筆記，爲我當下的問題提供決策建議。

## 3. 資料使用與幻覺控制
請嚴格遵守以下資料使用模式：[在此處填寫資料使用模式]

示例 1 (嚴格依據源文件)：你的回答必須 100% 基於我上傳的源文件。如果源文件中沒有提到的信息，直接回答“源文件中未提及”，嚴禁動用你的訓練數據進行猜測。每條關鍵結論後，必須標註引用來源，例如 [來源 1]。
示例 2 (混合增強模式)：以源文件的內容爲核心骨架。但在必要時，允許你調用外部訓練數據來解釋源文件中晦澀的術語，或補充相關的行業背景案例，以豐富內容。

## 4. 思考與分析框架
在回答問題前，請遵循以下思維邏輯：[在此處填寫思維邏輯]

示例 1 (視頻腳本邏輯)：痛點切入 -> 價值主張 -> 實操步驟 -> 引導關注。
示例 2 (利弊評估邏輯)：核心優勢 -> 致命缺陷 -> 適用人羣 -> 最終建議(推薦/不推薦)。
示例 3 (費曼技巧)：先用小學生能聽懂的話概括 -> 再深入技術細節 -> 最後用一個比喻來鞏固理解。

## 5. 輸出格式規範
請按照以下格式進行輸出：[在此處填寫輸出格式]

示例 1 (自媒體文案風格)：標題使用吸引眼球的標題，適當使用 Emoji 表情。正文結構要多分段，每段不超過3行，多使用短句，模擬真人口語感。
示例 2 (專業研報風格)：層級結構必須使用 H2 和 H3 清晰劃分章節。遇到對比類信息，強制使用 Markdown 表格進行展示。遇到專業名詞時，請保留英文原文並附帶中文解釋。

## 6. 負向約束
在生成內容時，請遵守以下約束：[在此處填寫負向約束]

示例 1：嚴禁使用“作爲一個AI語言模型”、“希望能幫到你”等無意義的填充詞。不需要寒暄，直接給出答案。
示例 2：不要說“很多公司”，要具體說“如亞馬遜或微軟”（如果源文件有提及）。嚴禁使用擬人、排比等花哨的修辭手法，保持客觀冷靜。
```

> [!WARNING] 重要提醒
> NotebookLM **不保存聊天曆史**！刷新頁面對話就沒了。
> **解決辦法：** 養成好習慣，覺得有用的回答，馬上點擊“儲存至記事”。

## 5. 深度補全：Deep Research 的優化方式

NotebookLM 的 Deep Research 和 ChatGPT/Gemini 的 Deep Research 用途完全不同，提示詞策略也要調整。

| 對比維度 | NotebookLM Deep Research | 通用 AI (GPT/Gemini) Deep Research |
| :--- | :--- | :--- |
| **核心定位** | **補全資料庫** | **直接出成品** |
| **使用場景** | 手頭資料不夠、太舊，需要找點東西補充進來，作爲新的信源。 | 直接拿去彙報、演講，或者發給老闆。 |
| **提示詞重點** | 側重研究範圍（時間/地域）、信源偏好（論文/論壇），目的是**互補**。 | 側重輸出結構、表達邏輯。 |

**優化技巧：**
- 優化Deep Research的提示詞結構
- 用 GPT/Gemini 做深度搜索，生成報告後，導入到 NotebookLM 裏作爲信源使用。

提示詞樣例：
````markdown
### 1. 角色設定
你是一個深度研究引擎，負責基於現有資料與網絡信息進行系統性研究、分析與整合。
產出的內容將作爲 NotebookLM 筆記本中的長期知識來源，而非一次性成稿。

示例：
- 行業研究分析員
- 技術趨勢研究員
- 市場與競爭分析顧問
- 學術綜述助理
- 政策與法規研究員

### 2. 研究目標
- 核心研究問題：<明確本次研究要解決什麼問題>
- 最終用途：<知識庫建設 / 決策支持 / 視頻腳本素材 / 寫作資料 / 趨勢判斷等>

示例：
- 核心研究問題：2024–2026 年個人 AI Agent 的主要技術路線與落地瓶頸
- 最終用途：爲視頻內容與長期知識庫提供可靠資料來源

### 3. 研究範圍與邊界
- 時間範圍：<例如 2020–2025 / 近三年 / 近一年>
- 地域範圍：<全球 / 中國 / 北美 / 歐洲等>
- 內容側重：<技術 / 產品 / 市場 / 學術 / 政策>
- 排除內容：營銷軟文、無明確來源的博客、純主觀觀點、重複或低信息密度內容

### 4. 來源篩選與引用規則
在抓取信息時，請優先採納以下類型的來源：
- 第一優先級：[在此處填寫，如：官方文檔、GitHub Readme、SEC財報]
- 第二優先級：[在此處填寫，如：Arxiv論文、知名科技媒體深度報道]
- 第三優先級：[在此處填寫，如：Reddit 高贊討論貼、Hacker News 評論（用於獲取真實反饋）]

所有關鍵結論必須附帶可追溯的來源說明。
若資料中未明確提及相關信息，請直接標註“源資料中未提及”，不得自行推斷或補充。

### 5. 分析與思考要求
針對每一個關鍵發現，必須包含以下內容：
- 事實本身：發生了什麼，有哪些數據或證據
- 成因分析：爲什麼會出現這種情況
- 不同觀點或分歧：是否存在不同解釋或爭議
- 趨勢判斷：未來可能的變化方向
- 實際意義：對決策、判斷或知識庫建設的價值

避免僅做摘要式羅列，必須體現分析過程。

### 6. 輸出結構要求
以 Markdown 格式輸出，並嚴格遵循以下結構：

	1. 執行摘要：概括本次研究的核心發現。
	2. 關鍵事實與數據：
	   - 按重要性列出5-10個核心事實。
	   - 每個事實必須包含具體數據（如增長率、版本號、具體參數）。
	   - 必須在每個事實後附帶可追溯的來源鏈接。
	1. 觀點對比：
	   - 官方/主流觀點是什麼？
	   - 社區/反對觀點是什麼？
	1. 趨勢預判：基於收集到的信息，預測未來的短期趨勢。
	2. 未解之謎：目前網絡上仍缺乏確切信息的問題有哪些（防止幻覺）。

### 7. 表達規則
- 語言風格：專業、剋制、技術向
- 明確區分事實、推論與不確定判斷
- 禁止營銷化、情緒化表達
- 禁止模糊指代，主體需明確
- 信息不足時直接說明“無確切信息”

### 8. 自檢清單
在輸出完成前，請自行檢查：
- 所有關鍵結論是否都有來源支持
- 是否存在過度推斷或跳步結論
- 是否嚴格遵循既定研究範圍與結構
- 是否混入低質量或不可靠來源

````

## 6. 大容量音視頻與批量導入

### 6.1 超大音視頻處理（YouTube大法）
如果你有幾個小時的會議錄音、講座視頻，文件太大傳不上去怎麼辦？
1.  把視頻/音頻上傳到 **YouTube**。
2.  設置爲 **“非公開” (Unlisted)**。
3.  複製鏈接，作爲來源添加到 NotebookLM。

### 6.2 批量導入技巧
避免一個一個手動複製YouTube視頻鏈接，使用瀏覽器插件：
*   **YouTube to NotebookLM**：一鍵把博主的所有視頻、播放列表導入筆記。
*   **NotebookLM 網頁導入器**：把網頁圖文一鍵存入（免費版有數量限制）。
*   **Save to Google Drive (谷歌官方)**：把網頁內容存到雲盤（這是我最推薦的，官方插件，無限制。）。

### 9.1 純文本合併 (TXT/Markdown)
不用裝環境，不用學複雜的編程，Windows/Mac 自帶的命令行就能跑。
**Shell 腳本代碼：**
注意：如果經常使用類似腳本，建議統一安裝PowerShell 7，這樣不管是windows還是mac行爲都一致。
當然，如果什麼都不安裝，那麼下面的代碼依然有效：
- Windows版：
```powershell
Get-ChildItem -File |
Where-Object { $_.Extension -in '.txt', '.md' } |
Sort-Object Name |
ForEach-Object {
    "`n`n# $($_.Name)`n" +
    (Get-Content $_.FullName -Raw -Encoding UTF8) +
    "`n`n---`n"
} |
Set-Content .\Combined_Knowledge.txt -Encoding UTF8

```
- MacBook版：
```bash
#!/bin/zsh

output="Combined_Knowledge.txt"
: > "$output"   # 清空 / 創建文件

for file in $(ls *.txt *.md 2>/dev/null | sort); do
  echo -e "\n\n# $file\n" >> "$output"
  cat "$file" >> "$output"
  echo -e "\n\n---\n" >> "$output"
done

```

### 9.2 二進制文件合併 (PDF/Word/圖片/電子書)

**Python 合併二進制文件的代碼：**

```python
import shutil
import subprocess
from pathlib import Path
from pypdf import PdfMerger
from reportlab.pdfgen import canvas
from PIL import Image

# =========================
# 用戶只需要改這裏
# =========================
INPUT_DIR = Path(r"./input_files")
OUTPUT_FILE = "FINAL_NOTEBOOKLM.pdf"

TEMP_DIR = Path("_temp_pdfs")
TITLED_DIR = Path("_titled_pdfs")

IMAGE_EXTS = {".jpg", ".jpeg", ".png", ".webp"}
OFFICE_EXTS = {".docx", ".doc", ".pptx", ".xlsx"}
EBOOK_EXTS = {".epub", ".mobi"}

HAS_SOFFICE = shutil.which("soffice") is not None
HAS_EBOOK_CONVERT = shutil.which("ebook-convert") is not None

def run(cmd):
    subprocess.run(cmd, check=True, stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)

def prepare_dirs():
    TEMP_DIR.mkdir(exist_ok=True)
    TITLED_DIR.mkdir(exist_ok=True)

def clean_dirs():
    shutil.rmtree(TEMP_DIR, ignore_errors=True)
    shutil.rmtree(TITLED_DIR, ignore_errors=True)

def office_to_pdf(src: Path) -> Path:
    if not HAS_SOFFICE:
        raise RuntimeError("未檢測到 LibreOffice（soffice）")
    run(["soffice", "--headless", "--convert-to", "pdf", str(src), "--outdir", str(TEMP_DIR)])
    return TEMP_DIR / f"{src.stem}.pdf"

def image_to_pdf(src: Path) -> Path:
    pdf_path = TEMP_DIR / f"{src.stem}.pdf"
    Image.open(src).convert("RGB").save(pdf_path)
    return pdf_path

def ebook_to_pdf(src: Path) -> Path:
    if not HAS_EBOOK_CONVERT:
        raise RuntimeError("未檢測到 ebook-convert（Calibre）")
    pdf_path = TEMP_DIR / f"{src.stem}.pdf"
    run(["ebook-convert", str(src), str(pdf_path)])
    return pdf_path

def create_title_page(title: str, output: Path):
    c = canvas.Canvas(str(output))
    c.setFont("Helvetica-Bold", 24)
    c.drawString(72, 720, f"# {title}")
    c.save()

def prepend_title_page(pdf: Path) -> Path:
    title_pdf = pdf.with_suffix(".title.pdf")
    create_title_page(pdf.name, title_pdf)
    merger = PdfMerger()
    merger.append(str(title_pdf))
    merger.append(str(pdf))
    output = TITLED_DIR / pdf.name
    merger.write(str(output))
    title_pdf.unlink(missing_ok=True)
    return output

def main():
    if not INPUT_DIR.exists():
        print("❌ 輸入目錄不存在")
        return
    prepare_dirs()
    processed = []
    for file in sorted(INPUT_DIR.iterdir()):
        if not file.is_file():
            continue
        ext = file.suffix.lower()
        try:
            if ext == ".pdf":
                pdf = TEMP_DIR / file.name
                shutil.copy(file, pdf)
            elif ext in IMAGE_EXTS:
                pdf = image_to_pdf(file)
            elif ext in OFFICE_EXTS:
                pdf = office_to_pdf(file)
            elif ext in EBOOK_EXTS:
                pdf = ebook_to_pdf(file)
            else:
                continue
            processed.append(prepend_title_page(pdf))
        except Exception as e:
            print(f"[失敗] {file.name}: {e}")
    if not processed:
        print("⚠️ 沒有成功處理任何文件")
        return
    merger = PdfMerger()
    for pdf in processed:
        merger.append(str(pdf))
    merger.write(OUTPUT_FILE)
    print(f"\n✅ 已生成：{OUTPUT_FILE}")

if __name__ == "__main__":
    clean_dirs()
    main()

```
